# Demo installation boundary

Demo memakai **satu instalasi dan satu database per skenario**, bukan tenant tersembunyi dalam database produksi. Operator menyediakan checkout/deployment, APP_KEY, host/cookie, database login yang hanya berhak atas database demo, storage dan worker terpisah. Untuk beberapa pengunjung/skenario privat, jalankan beberapa instalasi; jangan memakai database/worker yang sama dengan produksi. Tidak ada deployment demo nyata yang dibuat dalam pengerjaan ini.

Konfigurasi wajib: APP_ENV=demo (local/testing juga diizinkan), DEMO_FEATURES_ENABLED=true, DEMO_SCENARIO_ID UUID, DEMO_OPERATOR_TOKEN acak minimal32karakter. Nama database harus tepat `hris_demo_` diikuti UUID tanpa tanda hubung. MAIL_MAILER=array, QUEUE_CONNECTION=database, CACHE_STORE=database, SESSION_DRIVER=database; custom DB connections untuk session/cache/locks/queue tidak diizinkan. Failed jobs/batches wajib connection database default yang sama. Jangan menyalin kredensial integrasi produksi. Storage local diarahkan otomatis ke storage/app/demo/{UUID}/private, cookie session memakai suffix skenario. Gunakan role database khusus dan worker hanya deployment itu.

Pada database kosong bernama tepat tersebut, jalankan migrate, lalu `php artisan hris:demo init UUID`. Migrasi menulis marker demo yang harus cocok config. Init menolak database yang sudah berisi company/employee/user. Seed menciptakan delapan akun sintetis dengan email .invalid, password acak yang tidak dibagikan, persona roles, workflow, tujuh shift, sample saldo dan kebijakan payroll **draft** berlabel SIMULATED. Data bank/identitas/foto nyata tidak disalin; seed tidak menyetujui kebijakan produksi. Semua dokumen/slip/report demo di-watermark, HTML memiliki banner dan respons diberi X-HRIS-Environment/X-HRIS-Scenario.

Route /demo hanya didaftarkan jika fitur aktif dan environment memenuhi guard. GET /demo/personas serta POST /demo/persona, /demo/time dan /demo/clock memerlukan header X-Demo-Operator-Token. POST juga memakai CSRF session web dan throttle30/menit. Token hanya untuk operator skenario privat, jangan ditempel pada JavaScript publik atau URL. Persona dipilih memakai code whitelisted yang dipetakan server; tidak menerima employee_id/scenario_id bebas. Login demo mengesahkan sesi sintetis/MFA khusus instalasi tersebut dan diaudit. Endpoint produksi tetap menolak parameter simulation/occurred_at/employee_id/scenario_id.

UI /demo/operator hanya terdaftar saat demo aktif dan marker instalasi tervalidasi. Token diisi operator, dikirim sebagai header, dan tidak ditanam dari konfigurasi ke HTML/URL/local storage. Operator dapat memilih persona, waktu lokal/zona dan clocking shift sendiri. Pergantian persona menavigasi ulang untuk CSRF baru; tidak ada reset destruktif melalui web.

POST /demo/time menerima ISO8601 time dan mengubah ScenarioClock pada database instalasi ini. Tidak memanggil Carbon::setTestNow atau mengubah jam OS/global. Clock ini dipakai attendance dan penerbitan dokumen; validasi kalender kebijakan/scheduler lainnya tetap tanggal operasional server. Untuk perjalanan kalender lintas modul gunakan fixture bertanggal saat ini dan lingkungan pengujian otomatis; kontrol waktu UI tidak mengubah cakupan engine tersebut. Sesi dalam satu skenario berbagi jam skenario tersebut; skenario berbeda harus instalasi terpisah.

POST /demo/clock membawa idempotency_key, roster_shift_id, direction in/out, mode inside/outside/poor_accuracy. Server mengambil koordinat dari lokasi shift dan menjalankan engine geofence/akurasi yang sama. Hanya shift subjek sesi yang dipakai. Event sukses menyimpan provenance=SIMULATED, scenario_id dan actor_id; received_at tetap waktu penerimaan server. Data lain tetap hanya sintetis dalam database bertanda demo, dengan actors/audit yang dapat ditautkan ke persona dan skenario instalasi. Export bank operasional ditolak; email memakai array mail sink. Report/slip watermark tetap wajib meski fitur dijalankan di local/testing.

Reset hanya operator terminal: `php artisan hris:demo reset UUID`. Kode memverifikasi flag, environment, **nama database tepat, storage root, durable marker dan UUID argumen** sebelum migrate:fresh. Hanya database skenario ini di-reset; file attachment berpola path internal yang tercatat di database skenario dibersihkan lewat disk privat skenario. Session/job/cache database itu ikut hilang. User web tidak mendapat endpoint reset. Marker kind/UUID dilindungi trigger UPDATE/DELETE/TRUNCATE; waktu skenario boleh berubah. Database demo yang di-restore ke mode produksi ditolak oleh middleware, command hris dan queue worker.

DemoIsolationTest membuat nama database acak yang sesuai skenario, memigrasi/seed, menguji GPS/clock/banner/bank denial, mereset **database disposable itu saja**, lalu menghapusnya. Database hris/hris_testing tidak pernah di-reset oleh tes ini. Kredensial pengujian memerlukan CREATEDB; deployment demo seharusnya memakai role lebih terbatas sesudah provisioning.

# Delegasi, kalender tenggat dan preferensi notifikasi

POST workflow-delegations menerima delegate_id, role (manager/hr_admin/hr_officer/finance_approver), employee_ids eksplisit maksimal200, starts_at/ends_at ISO8601 maksimal90hari dan reason. Delegator hanya dapat menyerahkan kewenangan yang masih dimilikinya untuk setiap subjek. Delegate harus aktif, memiliki mandat role terkait serta MFA; tidak harus sudah memegang scope subjek karena delegation merupakan izin terbatas tersendiri. Scope tidak menyebar ke seluruh direktori/profil. Self-approval, pengaju/subjek dan rantai delegasi tidak diterima. Revoke hanya oleh delegator melalui {id}/revoke.

Base approvers tersimpan terpisah. Delegate aktif ditambahkan ke snapshot tahap dengan delegation IDs. Runtime memeriksa tanggal, pencabutan, mandat delegate, kewenangan delegator serta subjek setiap kali melihat/memutuskan. Scheduler merekonsiliasi delegasi future/expired dan approver yang tidak lagi sah pada pending/blocked, mencatat before/after IDs dan menaikkan versi request. Tidak memilih manager pengganti otomatis. Kandidat kosong memblokir, tidak auto-approve. Counterparty swap tidak didelegasikan. Decision history append-only menyimpan actor sebenarnya dan workflow_delegation_id.

Delegate HR/Finance dapat membuka proposed-profile/proposed-compensation dan evidence hanya untuk request yang ditugaskan, tanpa memperoleh akses umum ke kategori profil di luar scopenya. Medical evidence tetap tidak dibuka kepada manager. Delegasi dicabut/expired langsung menolak detail sensitif meskipun scheduler belum jalan.

Definisi workflow dapat memiliki deadline_calendar: timezone IANA, branch_id, working_days ISO1–7, start_local/end_local, due_minutes dan escalate_minutes. Mesin menghitung menit kerja dan melewati weekend serta work_calendar_dates holiday versi terakhir. Step membekukan konfigurasi/holiday-version dan instant hasilnya pada aktivasi. Zona berbeda dari host disimpan dengan offset, bukan diasumsikan waktu Jakarta. Default definisi lama tanpa calendar tetap elapsed24/48jam untuk kompatibilitas; gunakan konfigurasi eksplisit sebelum menetapkan SLA kerja produksi.

GET/POST notification-preferences milik akun sendiri: email_enabled, in_app_enabled, timezone, delivery_mode immediate/daily, digest_time dan pasangan quiet_start/quiet_end. Opt-out hanya mengubah kanal; state workflow/tugas tetap sumber kebenaran. Quiet hours, termasuk lintas tengah malam, menunda tanpa menghabiskan attempt. Daily menggabungkan maksimal1000event berizin menjadi email generik per akun/tanggal lokal; backlog sisanya dialihkan ke hari berikutnya. Tidak ada nominal salary/alasan medis/evidence dalam email. Slip notification tidak mendahului release_at.

Inbox dan delivery memeriksa ulang akses subjek; pindah scope/revoke tidak membuka detail lama. Lease dan Message-ID stabil mengurangi duplikasi, tetapi SMTP tetap at-least-once jika crash sesudah kirim sebelum status sent. Maksimal5attempts; retry manual operator beralasan diaudit. Preference/delegation/calendar API belum seluruhnya terhubung ke form preview; SMTP nyata serta beban besar belum UAT. Scheduler juga menghapus byte export yang kedaluwarsa setelah24jam, menyisakan metadata audit.
